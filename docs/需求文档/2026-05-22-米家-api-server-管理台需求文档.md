# 米家 API Server 管理台需求文档

版本：v0.1
日期：2026-05-22
状态：已确认第一版方向

## 1. 项目定位

基于当前 `mijiaAPI_V2` Python SDK，新增一个可长期运行的米家 API Server，并提供 Vue3 + Element Plus 管理台。项目目标是让用户用自己的米家账号部署自己的服务，对内网和公网提供标准 REST API，供脚本、AI Agent、其他后端或通用 API 客户端调用。

当前 SDK 继续保持核心库定位，新增 Server 和 Web 作为上层应用。

## 2. 核心原则

1. 单米家账号，不做多账号、多租户、账号托管或平台化服务。
2. 服务可被公网调用，因此默认重视鉴权、权限、审计和脱敏。
3. 部署方式不作为业务功能，项目只保证服务可运行、可配置、可验证。
4. 不依赖 Redis，默认使用内存 TTL 缓存和 SQLite 持久化缓存。
5. 管理台不直接控制 Docker、宿主机、systemd 或部署环境。
6. 前端构建后由后端 FastAPI 托管，最终用户只需要启动一个服务。

## 3. 技术架构

### 3.1 后端

新增 `server/` 目录：

- 使用 FastAPI 作为 API Server。
- 调用现有 `mijiaAPI_V2/` SDK 能力。
- 使用 SQLite 作为本地数据存储。
- 数据目录可配置。
- 提供 REST API、管理后台 API、健康检查、自检和 CLI。

### 3.2 前端

新增 `web/` 目录：

- 使用 Vue3、Vite、TypeScript。
- 使用 Element Plus 作为组件库。
- 开发期前后端分离。
- 构建后静态文件交给 FastAPI 托管。

### 3.3 SDK

- `mijiaAPI_V2/` 保持核心库定位。
- 不把 Web 服务、管理后台、数据库逻辑塞进 SDK 核心层。

## 4. 存储设计

SQLite 默认保存：

- 管理员账号哈希。
- API Key 哈希、权限、状态、备注。
- 配置快照与运行时配置。
- 设备别名、slug、标签、分组、隐藏状态。
- 设备和场景授权关系。
- 审计日志。
- 持久化缓存。
- 初始化状态。

米家凭据单独保存到受保护凭据文件，不和普通业务数据混放。

缓存策略：

- 内存 TTL 缓存：设备状态、短期请求结果。
- SQLite 缓存：家庭、设备、场景、设备规格、翻译和映射信息。
- 缓存表带 `expires_at`。
- 不做 Redis。
- 不做定时同步。

## 5. 初始化流程

首次打开管理台时进入初始化向导：

1. 创建唯一管理员账号。
2. 设置管理员密码。
3. 设置公网访问策略和 IP 白名单。
4. 配置 `PUBLIC_BASE_URL`、CORS、OpenAPI 开关等基础项。
5. 扫码登录米家。
6. 同步家庭、设备、场景。
7. 设置设备 slug、别名、隐藏状态、可控权限。
8. 创建第一个 API Key。
9. 显示服务自检结果和 API 调用示例。

初始化完成后进入总览仪表盘。

## 6. 管理后台页面

第一版保留以下页面：

1. 总览仪表盘。
2. 系统自检。
3. 米家登录。
4. 家庭与设备。
5. 场景管理。
6. API Key 管理。
7. 权限授权。
8. 配置中心。
9. 日志与审计。
10. 系统安全。
11. API 文档入口。

不做独立缓存管理页面，缓存刷新和清理放进配置中心或设备页的小操作。

不做部署助手页面，只显示服务状态、版本、配置摘要和自检结果。

## 7. 米家登录

第一版只支持二维码登录：

- 后台点击开始登录。
- 后端创建二维码登录会话。
- 前端展示二维码。
- 前端轮询登录状态。
- 登录成功后保存凭据。
- 显示账号状态、凭据状态、刷新状态。
- 支持重新登录、刷新凭据、清除凭据。

第一版不做账号密码登录。

## 8. 管理员安全

管理后台：

- 初始化时创建唯一管理员。
- 默认用户名为 `admin`。
- 密码只保存哈希。
- 登录成功后发管理后台会话 token。
- 默认会话有效期为 12 小时。
- 支持主动退出和修改密码。
- 连续 5 次失败锁定 15 分钟。
- 忘记密码只允许通过本机 CLI 重置。

公网策略：

- 管理台默认建议内网访问。
- 支持公网访问。
- 支持 IP 白名单。
- 支持登录失败锁定。
- 支持强密码策略。
- 支持访问日志脱敏。

## 9. API Key 鉴权

对外 API 使用 API Key：

- 请求头为 `Authorization: Bearer <api_key>`。
- 创建时只显示一次完整 Key。
- 数据库只保存哈希。
- 列表只显示前缀。
- 支持名称、备注、过期时间。
- 默认不过期。
- 支持禁用、删除、轮换。
- 禁用后立即失效。
- 记录最后使用时间、最后使用 IP、调用次数。

权限模型采用能力权限和资源授权两层。

能力权限：

- `read:status`
- `read:devices`
- `write:devices`
- `write:scenes`
- `manage:cache`
- `read:logs`

资源授权：

- 可访问哪些家庭。
- 可访问哪些设备。
- 可执行哪些场景。
- 设备只读或可控。
- 默认新 API Key 没有危险权限。

## 10. 设备与场景

### 10.1 设备管理

- 内部保存米家原始 `did`。
- 对外 API 优先使用内部 ID 或 slug。
- 默认脱敏原始 `did`。
- 管理台高级详情可查看原始值。
- 支持设备别名、slug、标签、分组。
- 支持隐藏设备。
- 支持设备只读和可控配置。

### 10.2 设备同步

- 初始化后同步一次。
- 后台支持手动重新同步。
- API 可按需刷新。
- 设备实时状态按需查询。
- 不做定时同步。
- 同步失败不阻塞服务启动。

### 10.3 设备控制

- 支持底层 `siid`、`piid`、`aiid`、`value` 控制。
- 支持常见快捷控制：开关、亮度、色温、温度、模式等。
- 快捷控制由后端根据设备规格和映射生成。
- 管理台高风险操作需要二次确认。
- 对外 API 不做交互确认，依赖权限和白名单。

## 11. 对外 API

MVP 必做：

- 服务健康、版本、运行时间。
- 米家账号登录状态。
- 扫码登录、重新登录、刷新凭据。
- 家庭列表。
- 房间列表。
- 设备列表。
- 设备实时状态。
- 设备属性控制。
- 批量控制。
- 设备规格查询。
- 场景列表与执行。
- 缓存刷新和清空。
- 日志摘要。
- OpenAPI JSON 和调试页。

暂不做：

- Home Assistant 专用适配。
- Agent 专用聚合接口。
- Webhook 或事件推送。
- 反向代理、HTTPS、域名、证书管理。

API 示例：

- `GET /api/v1/status`
- `GET /api/v1/account`
- `GET /api/v1/homes`
- `GET /api/v1/devices`
- `GET /api/v1/devices/{device_slug}`
- `GET /api/v1/devices/{device_slug}/state`
- `POST /api/v1/devices/{device_slug}/properties`
- `POST /api/v1/devices/{device_slug}/actions`
- `GET /api/v1/scenes`
- `POST /api/v1/scenes/{scene_id}/execute`
- `POST /api/v1/cache/refresh`

统一错误格式：

```json
{
  "error": {
    "code": "DEVICE_OFFLINE",
    "message": "设备当前离线",
    "details": {},
    "request_id": "..."
  }
}
```

## 12. OpenAPI 策略

- 默认关闭。
- 后台手动开启。
- 开启后仍需鉴权。
- 可配置只允许内网访问。
- 管理台可复制 OpenAPI 地址。
- AI Agent 或脚本可通过标准 OpenAPI 了解接口。

## 13. 配置中心

配置分层：

- 启动配置来自 `.env` 或配置文件。
- 运行时配置来自 SQLite。
- 后台展示配置来源：环境变量、配置文件、数据库。
- 可热更新配置立即生效。
- 需重启配置只保存并提示需要重启服务进程。
- 不假设用户使用 Docker。

配置项包括：

- 服务端口。
- `PUBLIC_BASE_URL`。
- CORS 来源。
- API 文档开关。
- 日志级别。
- 时区。
- 米家 API base URL。
- 请求超时。
- 重试次数。
- 缓存 TTL。
- 凭据路径。
- 文件缓存目录。
- 管理员密码。
- API Key 管理。
- 公网管理台访问。
- IP 白名单。
- 登录失败锁定。
- 访问日志脱敏。

## 14. 日志与审计

默认保留 30 天。

必须记录：

- 管理员登录成功或失败。
- API Key 创建、禁用、删除。
- 米家扫码登录、凭据刷新、凭据清除。
- 设备控制请求。
- 场景执行请求。
- 配置修改。
- 权限授权修改。
- API 请求失败摘要。

日志字段：

- 时间。
- 来源 IP。
- API Key 前缀或管理员身份。
- 请求路径。
- 操作类型。
- 结果。
- 耗时。
- `request_id`。

禁止记录：

- 米家 token 明文。
- API Key 明文。
- 管理员密码。
- 完整敏感请求体。

## 15. 系统自检

系统自检用于判断当前服务是否可用。

检查项：

- 后端服务是否正常。
- SQLite 是否可写。
- 配置文件是否可读写。
- 数据目录是否可写。
- 米家凭据是否存在且有效。
- 米家 API 是否可连通。
- 家庭、设备、场景是否已同步。
- API Key 是否已创建。
- OpenAPI 是否按配置启用。
- `PUBLIC_BASE_URL` 是否配置。
- 管理台公网暴露风险。
- IP 白名单是否开启。
- 关键安全项是否存在风险。

## 16. CLI

提供轻量命令行工具：

```bash
mijia-server init
mijia-server run
mijia-server check
mijia-server diagnose
mijia-server reset-admin
```

CLI 用于：

- 初始化数据库。
- 运行服务。
- 自检。
- 导出诊断信息。
- 重置管理员密码。
- 清理过期审计日志。
- 生成配置模板。

## 17. MVP 验收标准

MVP 完成时必须满足：

1. 新环境启动后能打开管理台。
2. 首次初始化能创建管理员。
3. 能通过二维码登录米家。
4. 能同步家庭、设备、场景。
5. 能设置设备 slug、隐藏状态和可控权限。
6. 能创建 API Key。
7. API Key 能按权限访问 API。
8. 无权限 API Key 控制设备会被拒绝。
9. REST API 能获取设备状态、控制设备、执行场景。
10. OpenAPI 默认关闭，开启后仍需鉴权。
11. 审计能看到登录、配置、控制、API Key 事件。
12. 重启服务后配置、凭据、API Key、授权仍然存在。
13. 无 Redis 环境下完整可用。
14. 前端构建后由后端单服务托管。
15. 系统自检能明确指出当前是否可用。
