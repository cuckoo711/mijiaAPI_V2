# 管理台图文使用教程

本教程于 **2026-10-17** 根据当前 **3.9.1** 代码运行的管理台制作，附 **17 张浏览器实截图片**，覆盖现有服务的主要操作流程。

截图使用隔离示例数据：演示家庭、客厅灯、书房插座、卧室温湿度计；未登录真实米家账号，未执行真实设备控制或场景。状态与规格示例用于说明页面操作，不证明真实设备兼容性或物理验收；登录二维码不落盘。

截图实例仅监听本机 `http://127.0.0.1:18123`，使用 HTTP 展示页面。实际使用时，请以自己部署的服务地址、协议、账号授权和设备返回结果为准。截图来源与维护说明见[图片说明](assets/管理台教程/README.md)。

已有服务的推荐操作顺序：**登录管理员 → 米家扫码授权 → 同步资源 → 查看设备 → 创建只读 Key → 验证 API → 按需开放控制**。仅使用 SDK 的读者请看[SDK 快速开始](01-快速开始.md)。

## 1. 打开服务并登录管理员

**目标：** 进入已有服务的管理台。先确认服务已经启动，再用浏览器打开部署地址；默认监听地址为 `127.0.0.1:8123`，访问协议以启动日志或部署配置为准。

首次使用且尚无管理员时，输入用户名与密码，点击“初始化”。用户名至少 3 个字符，密码至少 8 个字符。初始化只需完成一次；已有管理员的服务直接进入登录步骤。

![首次初始化管理员](assets/管理台教程/01-初始化.jpg)

出现“管理员登录”后，填写管理员用户名、密码，点击“登录”。登录成功后可查看总览；右上角“改密”用于修改管理员密码，“退出”用于结束管理台会话。

![管理员登录](assets/管理台教程/02-管理员登录.jpg)

**成功信号：** 出现总览和完整管理页面。管理员账号与米家账号各自承担不同作用：前者登录本服务，后者授权本服务读取或操作米家资源。

**常见问题：** 页面打不开时先检查服务进程、端口与访问地址。首次初始化提示仅允许本机访问时，请在服务器本机完成；Docker/私网部署的首次初始化方法见文末运维说明。自签证书的信任问题应按部署环境处理。

## 2. 从总览了解当前状态

**目标：** 判断下一步应登录米家、同步资源，还是开始使用 API。

总览展示“服务状态”“米家账号”“设备统计”和“API Key”。先看服务版本与运行状态，再核对账号有效性、家庭/设备/场景数量。左侧导航按运行管理、资源管理、访问控制、系统配置分组；窄屏可用左上角导航按钮展开菜单。

![总览](assets/管理台教程/03-总览.jpg)

**成功信号：** 版本、账号状态和资源数量正常显示。刚初始化或尚未同步时，数量为零属于正常现象。

**常见问题：** “运行正常”表示服务的对应状态检查通过，不能据此判断米家授权有效或设备已执行动作。图中“未登录”与已有资源同时出现，是因为隔离截图实例预置了示例清单；它不代表生产服务可以免授权同步。截图中的资源数量是演示数据，不应作为自己账号的预期数量。

## 3. 登录米家并同步家庭、设备和场景

**目标：** 将有权使用的米家资源同步到本服务。

进入“运行管理 → 米家登录”，点击“开始扫码登录”；已有凭据时按钮为“重新扫码登录”。按页面提示用米家完成扫码确认，等待显示“登录成功”，并核对上方账号状态。随后点击“同步家庭/设备/场景”，查看同步进度、当前家庭及资源统计，完成后进入资源管理页面。

![米家登录与同步入口](assets/管理台教程/04-米家登录.jpg)

**成功信号：** 账号凭据状态有效；同步进度变为“已完成”，家庭、设备、场景列表更新。若出现警告，应阅读具体家庭和错误内容，完成状态不代表没有遗漏。

**常见问题：** 二维码任务失效时点击“重新扫码登录”；读取状态异常可使用“重试读取状态”。同步状态读取失败时先“刷新同步进度”，避免反复创建任务。凭据过期需重新授权。

“移除账号”会删除本地米家凭据，取消相关登录任务，并清理该账号同步的家庭、设备、场景及 SDK 缓存。它不是简单收起页面；需要再次登录、同步后才能恢复使用，请勿把它当作刷新按钮。

## 4. 整理设备标识与控制权限

**目标：** 找到设备、设置外部调用标识，并决定哪些设备可控。

进入“资源管理 → 家庭与设备”，可按家庭、状态、访问、隐藏条件筛选；“重置”清除筛选。“重新同步”用于更新米家资源。设备显示名来自同步信息；需要修改 API 使用的设备标识时，编辑 `Slug` 后点击该行“保存”。

![家庭与设备](assets/管理台教程/05-家庭与设备.jpg)

“访问”默认为只读。将需要操作的设备切换为“可控”，开关会自动保存；“隐藏”开关也自动保存。隐藏设备不会出现在对外设备列表中，管理台仍可看到并查看状态，但不能直接控制。

窗口较窄时，在设备表格底部向右横向滚动，即可看到“访问”和“隐藏”列。

![设备访问权限与隐藏开关](assets/管理台教程/05b-设备权限.jpg)

“批量设置”可以全部开启或关闭设备控制，弹窗确认后生效。它作用于全部已加载资源，**包含隐藏项，不受当前筛选或分页影响**；它只调整授权，不会立即执行设备操作。场景页的批量设置采用同样范围。

**成功信号：** 出现保存成功提示，重新查看时权限与 Slug 保持一致。

**常见问题：** 切换访问/隐藏开关后无需再点保存；修改 Slug 则需要保存。只读状态不妨碍读取设备状态，切为可控也不代表具体属性一定支持写入。

## 5. 查看设备状态与手动控制入口

**目标：** 先读取状态与规格，再明确提交所需操作。

点击设备行的“状态与控制”，查看“当前属性状态”，需要时点击“刷新状态”。页面展示属性、SIID/PIID、值与读取结果。设备列表的在线状态来自上次同步；此窗口中的读取时间用于判断状态的新旧。

![设备状态与控制](assets/管理台教程/06-状态与控制.jpg)

在“设备规格与控制”中，先选择可写属性并填写值，或选择设备动作并填写参数。确认规格与参数后，才点击“确认写入属性”或“确认执行动作”。选择项目和填写参数本身不会发出控制请求；只读或隐藏设备需要先调整授权。

**成功信号：** 页面给出本次操作结果；随后刷新状态，并核对真实设备效果。接口成功提示、ACK 或审计记录不能替代实物确认。

**常见问题：** 没有可写属性或动作时，先“重新读取规格”，并检查设备实际支持能力。可读属性为空时也可能是规格未提供相应属性。显示“结果未知”时，命令可能已经送达，**不要立即重试**；先“核对最新状态”并检查实物，再点击“已核对结果，允许新的手动操作”。

## 6. 管理并手动执行场景

**目标：** 只执行已授权且未隐藏的场景。

进入“资源管理 → 场景管理”，核对场景名称、家庭及场景 ID。按需开启“允许执行”，关闭“隐藏”；这些开关自动保存。“批量设置”可一次调整全部场景执行授权，范围包含隐藏项。

![场景管理](assets/管理台教程/07-场景管理.jpg)

点击“执行场景”只会打开确认窗口。再次核对场景与家庭，点击“确认执行场景”才真正发送请求；“关闭”用于离开窗口。场景 ID 旁的复制图标复制的是执行用 `curl` 命令，运行前应核对地址和密钥。

![场景执行确认窗口](assets/管理台教程/08-场景确认.jpg)

**成功信号：** 返回成功结果，并观察场景涉及设备的实际效果。

**常见问题：** 按钮不可用时检查“允许执行”与“隐藏”。出现“结果未知”时不会自动重发，应先点击“查看设备状态”并核对效果；确认需要新操作后，再使用“已核对结果，允许再次手动执行”。

## 7. 为外部程序创建和管理 API Key

**目标：** 给脚本、自动化或其他程序分配独立访问凭据。

进入“访问控制 → API Key”，填写便于辨认的名称，至少选择一项权限。首次接入可选“读取服务状态”“读取家庭与设备”，先完成只读调用；确需控制时再授予“控制设备”或“执行场景”。设置家庭、设备、场景范围及过期时间后，点击“创建”。

![创建 API Key](assets/管理台教程/09-创建API-Key.jpg)

三个资源范围各自独立；限定家庭时，还应分别选择允许访问的设备、场景。勾选“全部”表示该类资源不限；取消后必须至少选一项。Key 的控制权限、资源范围与设备自身“可控”或场景“允许执行”必须同时满足。

完整密钥只显示一次，请立即保存到自己的凭据管理位置。列表显示名称、前缀、权限、范围、过期时间和调用次数，无法从前缀恢复完整密钥。

![API Key 管理](assets/管理台教程/10-密钥管理.jpg)

**成功信号：** 新 Key 出现在列表，使用它可完成所授权的请求。“停用”可暂停使用；“轮换”生成新密钥并继承权限与范围，成功后旧密钥失效（有效期可继承或重新设置）；“删除”确认后立即失效。

**常见问题：** 丢失完整密钥时请轮换并更新调用方。过期或停用的 Key 无法通过认证。控制失败时除检查 scope，还要检查资源范围及资源授权开关。教程截图不会展示可用完整密钥。

## 8. 用只读请求验证 API

**目标：** 验证地址、网络访问策略和 API Key，避免首次接入就触发设备动作。

进入“访问控制 → API 使用”，查看调用方式和接口表格；展开一行可阅读请求、返回值、注意事项及示例。外部请求通过 HTTP Header 传入 `Authorization: Bearer ...`，管理员浏览器登录状态不会代替 API Key。

![API 使用与接口说明](assets/管理台教程/11-API使用.jpg)

下面只读取设备列表。把示例域名替换为实际服务地址，并在自己的终端环境中设置 `MIJIA_API_KEY`；不要把真实密钥写进公开文档或截图。该 Key 至少需要“读取家庭与设备”权限。

Linux/macOS 的 shell 示例：

```bash
curl --fail --show-error \
  -H "Authorization: Bearer ${MIJIA_API_KEY}" \
  "https://mijia.example.com/api/v1/devices"
```

Windows PowerShell 示例；使用 `curl.exe` 明确调用 curl 程序：

```powershell
$mijiaTutorialBaseUrl = 'https://mijia.example.com'
curl.exe --fail --show-error -H "Authorization: Bearer $env:MIJIA_API_KEY" "$mijiaTutorialBaseUrl/api/v1/devices"
```

**成功信号：** 返回 JSON，`items` 中为该 Key 可见且未隐藏的设备；列表为空时先检查同步与资源范围。后续读取单设备、状态或规格时，使用列表返回的设备 Slug。

**常见问题：** 401 先检查是否携带正确的 Bearer 请求头；403 应结合响应中的 `error.code` 和 `message` 排查，无效、停用、过期或权限不足的密钥均可能返回 `API_KEY_FORBIDDEN`，来源访问策略或资源范围不符也会拒绝访问。Swagger/ReDoc 打不开时，到系统安全按需开启交互式文档。PowerShell 不识别 `curl.exe` 时先安装或启用 curl。

## 9. 按部署方式设置系统安全

**目标：** 让需要的调用方能够访问，并保持来源判断正确。

进入“访问控制 → 系统安全”。局域网使用需开启“允许局域网请求”；公网使用需开启“允许公网请求”。监听地址、端口映射、防火墙和反向代理也必须允许连接；如果服务仍监听 `127.0.0.1`，仅拨动开关不会让其他机器直接连接。

![系统安全](assets/管理台教程/12-系统安全.jpg)

使用反向代理时，按部署方案开启“反向代理模式”，每行填写一个可信代理 IP/CIDR，点击“保存可信代理”。“启用交互式文档”开放 Swagger/ReDoc，并允许加载 OpenAPI JSON；“开放 OpenAPI JSON”可单独开放接口定义，修改后立即生效。来源策略覆盖管理台、业务 API、文档页与健康检查，调整时应一并核对。

![传输安全与 API 文档选项](assets/管理台教程/12b-传输与文档.jpg)

**成功信号：** 预期客户端可使用自己的 Key 访问只读接口，服务能按真实来源判断策略。

**常见问题：** 图片仅展示隔离实例的当前设置，不是需要逐项照抄的部署模板。“自签证书”开关会立即改变 API 示例协议，但实际 HTTP/HTTPS 监听在下次启动时生效。`PUBLIC_BASE_URL` 也不会自行改变监听地址。公网部署的代理、证书与端口设置参见运维说明。

## 10. 自检、审计与配置维护

**目标：** 找到故障线索，并区分请求结果、审计保存与设备效果。

进入“运行管理 → 系统自检”，逐项查看检查项、说明、状态、结果；先处理“失败”，再判断“提醒”是否符合部署预期。此页没有独立运行按钮，可刷新管理台重新读取。

![系统自检](assets/管理台教程/13-系统自检.jpg)

截图未保存米家凭据，所以凭据项出现“提醒”符合本截图环境；真实服务仍需完成自己的扫码授权。

进入“系统配置 → 日志与审计”，点击“刷新审计”，按时间、动作、操作者与请求 ID 核对记录，展开行可查看元数据。队列有待补写记录时，可点击“补写审计”；此操作只重新保存审计，不会重新控制设备或执行场景。

![日志与审计](assets/管理台教程/14-日志与审计.jpg)

进入“系统配置 → 配置中心”，填写 `Key`、`Value` 后点“保存”，核对下方值和来源。常用 `PUBLIC_BASE_URL` 用于展示对外调用地址；访问策略优先使用系统安全中的对应开关设置。

![配置中心](assets/管理台教程/15-配置中心.jpg)

图中 `https://mijia.example.com` 仅为填写示例，尚未点击保存。大表格出现列遮挡时，可在表格底部横向滚动查看 Slug、权限或请求 ID。

**成功信号：** 自检结果符合预期，配置保存后重新读取一致，审计队列正常且能找到对应操作。

**常见问题：** “部分成功/警告”和“结果未知”应查看详情，不能视作全部执行成功。无效队列记录或历史未能保存事件需检查日志与存储；后者无法通过补写恢复，排查后还需按运维说明重启。服务就绪也不证明真实米家授权、设备状态或动作验收通过。
