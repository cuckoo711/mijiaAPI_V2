# 故障排查指南

本文档提供常见问题的排查方法和解决方案。

---

## 登录问题

### 二维码登录

```python
from mijiaAPI_V2 import create_auth_service

auth_service = create_auth_service()
credential = auth_service.login_by_qrcode()
auth_service.save_credential(credential)
```

二维码约 2 分钟有效，超时需重新生成。登录失败时：

1. 检查网络能否访问小米账号服务
2. 确认使用较新的米家 APP 扫码
3. 若曾成功登录，可直接加载已保存的凭据：`create_api_client_from_file()`

### 凭据加载失败（MAC check failed）

**症状**：
- 日志出现 `加载凭据失败: MAC check failed`
- 管理台或 SDK 提示「米家凭据不存在」但 `credential.json` 文件实际存在

**原因**：
凭据为 AES-GCM 密文，解密密钥与加密时不一致。常见情况：
- 只复制了 `credential.json`，未一并复制同目录的 `.credential_key`
- 更换了环境变量 `MIJIA_CREDENTIAL_SECRET`，与落盘密文不匹配
- 手动编辑过 `.credential_key`（该文件为二进制，不能当文本改）

**处理**：
1. 若有备份：同时恢复 `credential.json` 与 `.credential_key`（或统一 `MIJIA_CREDENTIAL_SECRET`）
2. 无备份：删除损坏的凭据与密钥后重新扫码登录
   ```bash
   rm -f configs/credential.json configs/.credential_key
   # 然后在管理台或 examples/01_authentication.py 重新登录
   ```

v3.7.3 起已修复「密钥文件首尾恰好为空白字节时被错误 strip」导致的偶发 MAC 失败（也会表现为 CI 单测间歇红）。

4. **查看详细日志**
   ```python
   import logging
   logging.basicConfig(level=logging.DEBUG)
   
   # 然后运行登录代码
   ```

**手动创建凭据（高级用法）**：

如果你已经有 `serviceToken` 和 `ssecurity`（例如从浏览器中提取），可以手动创建凭据：

```python
from datetime import datetime, timedelta
from mijiaAPI_V2.domain.models import Credential
from mijiaAPI_V2 import create_api_client

# 手动创建凭据
credential = Credential(
    user_id="your_user_id",
    service_token="your_service_token",
    ssecurity="your_ssecurity",
    device_id="your_device_id",
    user_agent="iOS-14.4-6.0.103-iPhone12,1",
    expires_at=datetime.now() + timedelta(days=7)
)

# 创建API客户端
api = create_api_client(credential)

# 保存凭据以便后续使用
from mijiaAPI_V2 import create_auth_service
auth_service = create_auth_service()
auth_service.save_credential(credential)
```

## 凭据过期问题

### 凭据过期无法刷新

**症状**：
- 调用API时提示 `TokenExpiredError`
- 刷新凭据失败

**解决方案**：

1. **检查凭据状态**
   ```python
   from mijiaAPI_V2 import create_auth_service
   
   auth_service = create_auth_service()
   credential = auth_service.load_credential()
   
   if credential:
       print(f"是否过期: {credential.is_expired()}")
       print(f"剩余时间: {credential.expires_in()} 秒")
   ```

2. **尝试刷新凭据**
   ```python
   try:
       new_credential = auth_service.refresh_credential(credential)
       auth_service.save_credential(new_credential)
       print("凭据刷新成功")
   except Exception as e:
       print(f"凭据刷新失败: {e}")
       print("需要重新登录")
   ```

3. **重新登录**
   如果刷新失败，需要重新登录获取新凭据。

## 网络问题

### 连接超时

**症状**：
- API调用超时
- 网络错误

**解决方案**：

1. **检查网络连接**
   ```bash
   # 测试网络连接
   ping account.xiaomi.com
   ping api.io.mi.com
   ```

2. **调整超时设置**
   ```python
   from pathlib import Path
   from mijiaAPI_V2.core.config import ConfigManager
   
   config = ConfigManager(Path("configs/mijiaAPI.toml"))
   config.set("DEFAULT_TIMEOUT", 60)  # 增加到60秒
   ```

3. **使用代理**
   如果在某些网络环境下无法访问米家服务器，可以配置代理：
   ```python
   import httpx
   
   # 配置代理（需要修改 CredentialProvider 代码）
   proxies = {
       "http://": "http://proxy.example.com:8080",
       "https://": "http://proxy.example.com:8080",
   }
   ```

## 缓存问题

### 缓存数据不一致

**症状**：
- 获取的设备状态与实际不符
- 控制设备后状态未更新

**解决方案**：

1. **主动刷新缓存**
   ```python
   # 刷新特定家庭的缓存
   api.refresh_cache(home_id="123456")
   
   # 刷新所有缓存
   api.refresh_cache()
   ```

2. **清空所有缓存**
   ```python
   # 谨慎使用！会清空所有用户的缓存
   api.clear_all_cache()
   ```

3. **禁用缓存**
   修改配置文件，将缓存TTL设置为0（不推荐）：
   ```toml
   [cache]
   device_list_ttl = 0
   device_state_ttl = 0
   ```

## 设备控制问题

### 设备控制失败

**症状**：
- `control_device()` 返回 `False`
- 抛出 `DeviceNotFoundError` 或 `PropertyReadOnlyError`

**解决方案**：

1. **检查设备是否在线**
   ```python
   device = api.get_device(device_id)
   if device and device.is_online():
       print("设备在线")
   else:
       print("设备离线")
   ```

2. **验证属性参数**
   - 确认 `siid`、`piid` 和 `value` 参数正确
   - 查看设备规格文档确认属性是否可写
   - 检查属性值范围是否合法

3. **查看详细错误信息**
   ```python
   try:
       api.control_device(device_id, siid, piid, value)
   except Exception as e:
       print(f"控制失败: {e}")
       import traceback
       traceback.print_exc()
   ```

## 依赖问题

### 缺少依赖库

**症状**：
- `ImportError` 或 `ModuleNotFoundError`

**解决方案**：

1. **安装所有依赖**
   ```bash
   uv sync
   ```

2. **安装可选依赖**
   ```bash
   # Redis支持
   uv pip install "mijia-api[redis]"
   
   # 开发工具
   uv pip install "mijia-api[dev]"
   ```

3. **检查Python版本**
   ```bash
   python --version
   # 需要 Python 3.9 或更高版本
   ```

## 性能问题

### API调用缓慢

**症状**：
- API调用响应时间长
- 批量操作耗时过长

**解决方案**：

1. **使用缓存**
   确保缓存功能已启用，避免重复请求。

2. **使用批量操作**
   ```python
   # 不好：逐个控制
   for device_id in device_ids:
       api.control_device(device_id, 2, 1, True)
   
   # 好：批量控制
   requests = [
       {"device_id": did, "siid": 2, "piid": 1, "value": True}
       for did in device_ids
   ]
   api.batch_control_devices(requests)
   ```

3. **使用异步API**
   ```python
   import asyncio
   from mijiaAPI_V2 import create_async_api_client
   
   async def main():
       api = create_async_api_client(credential)
       
       # 并发获取多个家庭的设备
       results = await asyncio.gather(
           api.get_devices(home_id_1),
           api.get_devices(home_id_2),
           api.get_devices(home_id_3),
       )
   
   asyncio.run(main())
   ```

4. **使用Redis缓存**
   对于多进程或分布式部署，使用Redis共享缓存：
   ```python
   import redis
   from mijiaAPI_V2 import create_api_client
   
   redis_client = redis.Redis(host='localhost', port=6379, db=0)
   api = create_api_client(credential, redis_client=redis_client)
   ```

## 日志调试

### 启用详细日志

如果遇到问题需要调试，可以启用详细日志：

```python
import logging
from mijiaAPI_V2.core.logging import get_logger

# 设置日志级别为DEBUG
logging.basicConfig(level=logging.DEBUG)

# 或者只设置特定模块的日志级别
logger = get_logger("mijiaAPI_V2.services.device_service")
logger.setLevel(logging.DEBUG)
```

**配置文件方式**：
```toml
[logging]
level = "DEBUG"
format = "json"
file = "logs/mijia_debug.log"
```

| 错误代码 | 描述 | 解决方案 |
|---------|------|---------|
| 70016 | 登录验证失败 | 已修复，使用最新版SDK |
| 401 | 凭据无效或过期 | 参见下方"401未授权错误"详细说明 |

| -1 | 网络错误 | 检查网络连接 |

## 401 未授权

API 返回 401 时优先检查：

1. 凭据是否过期（`credential.is_expired()`），过期则重新登录或刷新
2. `configs/credential.json` 与 `.credential_key` 是否成对存在
3. 开启 DEBUG 日志查看请求与响应细节

## API Server / 管理台

### 每次启动都提示「迁移到 v3.0」

已在 v3.7.0 起：SDK / Server 默认统一为 `configs/`；旧 `.mijia/` 迁移后**直接删除**（不留备份）。若仍看到迁移日志，确认工作目录是项目根且没有重新创建 `.mijia/`。

### 忘记管理员密码

本机执行：

```bash
uv run python -m server.cli reset-admin
# 或指定用户
uv run python -m server.cli reset-admin --username admin
```

### 管理台登录后接口 403 CSRF_FAILED

Cookie 会话下的写操作需要 `X-CSRF-Token` 与 `mijia_csrf` Cookie 一致。请使用官方管理台（会自动带上），或改用 `Authorization: Bearer`。跨域前端不要依赖 Cookie。

### NETWORK_ACCESS_DENIED

在「系统安全」开启局域网/公网访问。策略覆盖整站（含管理台）。经反代时仅在确认代理可信后开启 `TRUST_PROXY_HEADERS`，并配置 `TRUSTED_PROXY_CIDRS`。

### 查看占用与清理缓存

```bash
uv run python -m server.cli status
uv run python -m server.cli purge-cache          # 过期
uv run python -m server.cli purge-cache --all    # 全部
```
