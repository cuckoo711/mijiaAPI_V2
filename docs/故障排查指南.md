# 故障排查指南

## 米家登录与凭据

### 二维码登录失败

```python
from mijiaAPI_V2 import create_auth_service

auth_service = create_auth_service()
credential = auth_service.login_by_qrcode()
auth_service.save_credential(credential)
```

二维码过期后重新生成；使用米家 App 扫码并确认授权。失败时检查本机能否访问小米账号服务。已有有效凭据可用 `create_api_client_from_file()` 加载，无需重复扫码。

完整示例见[认证与凭据管理](../examples/01_authentication.py)。

### 凭据加载失败：`MAC check failed`

凭据文件存在却提示无法加载，通常是 AES-GCM 解密密钥与保存时不一致：

- 只复制了 `credential.json`，未复制同目录的 `.credential_key`。
- 修改了 `MIJIA_CREDENTIAL_SECRET`。
- 将二进制 `.credential_key` 当成文本编辑。

有备份时，成对恢复凭据和密钥，或恢复原 `MIJIA_CREDENTIAL_SECRET`。无法恢复时，移除损坏的凭据与密钥后重新扫码。默认路径见[配置文件说明](../configs/README.md)。

### 凭据过期或小米接口返回 401

```python
from mijiaAPI_V2 import create_auth_service

auth_service = create_auth_service()
credential = auth_service.load_credential()

if credential:
    print(f"是否过期: {credential.is_expired()}")
    print(f"剩余时间: {credential.expires_in()} 秒")
    if credential.is_expired():
        credential = auth_service.refresh_credential(credential)
        auth_service.save_credential(credential)
```

刷新失败或凭据已被小米撤销时，重新扫码登录。API Server 的 401 另见下方鉴权排查。

## 网络超时

1. 检查 DNS、HTTPS 连接、系统时间和证书；确认本机可访问 `account.xiaomi.com` 与配置的米家 API 地址。
2. 检查系统或网络代理是否可用。SDK 的 HTTP 客户端使用 httpx；代理环境变量应在创建客户端前设置。
3. 网络可达但响应较慢时，在创建客户端前设置环境变量 `MIJIA_DEFAULT_TIMEOUT=60`，将超时增加到 60 秒。

配置优先级和有效配置项见[配置说明](使用指南/03-配置说明.md)。

## 缓存数据与设备状态不一致

SDK 可使当前用户的缓存失效，下次查询时重新获取：

```python
api.refresh_cache(home_id="123456")  # 指定家庭
api.refresh_cache()                  # 当前用户的全部缓存
```

`api.clear_all_cache()` 会清空所有用户的缓存。管理台设备列表中的在线状态来自最近一次资源同步；需要最新属性时，打开「状态与控制」并刷新状态。

## 设备控制失败

1. 确认设备在米家 App 中在线且可控。
2. 查询设备规格，核对 `siid`、`piid`、`aiid`、属性写权限、值范围和动作参数。
3. API Server 中确认设备未隐藏且设为「可控」；API Key 还须具备对应能力和资源授权。
4. 查看返回的错误码、操作回执和审计记录。结果未知时先读取状态并核对设备，避免重复执行。

SDK 排查示例：

```python
from mijiaAPI_V2 import create_api_client_from_file

api = create_api_client_from_file()
device = api.get_device("your_device_id")
if device:
    print(device.name, device.status)
    print(api.get_device_spec(device.model))
```

设备列表、控制与异常接口见 [API 客户端参考](API参考/01-API客户端.md)和[异常处理](API参考/03-异常处理.md)。

## 缺少依赖

在项目根目录执行：

```bash
uv sync
```

按需安装可选依赖：

```bash
uv sync --extra redis
uv sync --extra dev
```

Python 版本要求见 [`pyproject.toml`](../pyproject.toml) 的 `requires-python`。

## API Server / 管理台

### 忘记管理员密码

在服务所在机器执行：

```bash
uv run python -m server.cli reset-admin
# 指定用户
uv run python -m server.cli reset-admin --username admin
```

### 接口返回 401 或 403

| 情况 | 排查方式 |
|------|----------|
| 管理员会话过期 | 重新登录管理台 |
| API Key 无效 | 核对 `Authorization: Bearer <api_key>`，检查 Key 是否过期、停用或已轮换 |
| API Key 权限不足 | 核对能力权限、家庭/设备/场景资源授权和资源本身的可控设置 |
| `CSRF_FAILED` | Cookie 会话的写操作须携带与 `mijia_csrf` Cookie 一致的 `X-CSRF-Token`；管理台会自动携带 |
| `NETWORK_ACCESS_DENIED` | 在「系统安全」检查局域网/公网访问开关和 IP 白名单 |

经反向代理访问时，确认代理可信后再开启 `TRUST_PROXY_HEADERS`，并配置 `TRUSTED_PROXY_CIDRS`。接口鉴权细节见 [API Server 开发说明](开发指南/05-API-Server-开发启动.md)。

### 每次启动都提示迁移旧数据

默认数据目录为 `configs/`。旧 `.mijia/` 及 `.mijia_backup*` 会在 Server 启动迁移后删除，不保留备份。反复出现迁移日志时，检查启动工作目录是否正确，以及是否有其他程序重新创建旧目录。

### 查看状态、诊断与缓存占用

```bash
uv run python -m server.cli status
uv run python -m server.cli check
uv run python -m server.cli diagnose
uv run python -m server.cli purge-cache        # 清理过期 SDK 磁盘缓存
uv run python -m server.cli purge-cache --all  # 清理全部 SDK 磁盘缓存
```

就绪检查和审计恢复见[部署运维说明](../deploy/README.md#依赖就绪与审计恢复)。

## 日志与问题反馈

SDK 启用调试日志：

```python
import logging

logging.basicConfig(level=logging.DEBUG)
# 仅调整设备服务日志级别
logging.getLogger("mijiaAPI_V2.services.device_service").setLevel(logging.DEBUG)
```

提交 [Issue](https://github.com/cuckoo711/mijiaAPI_V2/issues) 时提供版本、运行方式、复现步骤、错误码和 `request_id`。日志与诊断输出先检查脱敏，不附管理员密码、完整 API Key、米家凭据或加密密钥。
