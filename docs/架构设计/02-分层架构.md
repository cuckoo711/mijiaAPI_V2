# 分层架构

SDK 采用领域驱动 + 分层架构，源码在 `mijiaAPI_V2/`。本页只讲职责与依赖；类与方法见 [API 参考](../API参考/01-API客户端.md)、[领域模型](../API参考/02-领域模型.md)。

## 架构概述

```
API 客户端层   api_client.py / factory.py     → 对外统一入口
服务层         services/                      → 业务编排
仓储层         repositories/                  → 数据访问抽象
基础设施层     infrastructure/                → HTTP / 加密 / 缓存 / 凭据
领域层         domain/                        → 模型与异常（被所有层依赖）
```

依赖只允许向下（或指向领域层）；领域层不依赖任何外部 IO。

## 领域层 `domain/`

- `models.py`：`Credential`、`Device`、`Home`、`Scene`、`DeviceSpec` 等，Pydantic 校验；凭据带过期与序列化方法，设备状态用 `DeviceStatus` 枚举。
- `exceptions.py`：`MijiaAPIException` 及认证 / 设备 / 网络 / 验证子类，便于分层捕获。

原则：纯业务对象与规则，不做 IO。

## 基础设施层 `infrastructure/`

| 模块 | 职责 |
|------|------|
| `http_client.py` / `http_protocol.py` | 米家 API 请求、签名与重试 |
| `crypto_service.py` | RC4 / 签名 / nonce |
| `credential_provider.py` | 扫码登录、凭据刷新 |
| `credential_store.py` | 凭据 AES-GCM 落盘 |
| `cache_manager.py` | 磁盘 / 可选 Redis 缓存（TTL 由代码固定） |

## 仓储层 `repositories/`

面向接口（`interfaces.py`）提供家庭、设备、场景、规格的读写；`property_translations.py` 负责规格中文翻译。同步与异步实现分离，供服务层与客户端选用。

## 服务层 `services/`

| 服务 | 职责 |
|------|------|
| `AuthService` | 登录、刷新、存取凭据 |
| `DeviceService` | 设备列表、属性读写、批量控制、规格 |
| `SceneService` | 场景列表与执行 |
| `StatisticsService` | 设备统计 |

## API 客户端层 `api_client.py`

`MijiaAPI` / `AsyncMijiaAPI` 注入服务与 Home 仓储，不直接访问 HTTP。异步版本用 `asyncio.to_thread` 复用同步服务层，避免两套业务逻辑。

`factory.py` 负责组装：配置 → 基础设施 → 仓储 → 服务 → 客户端（`create_api_client`、`create_async_api_client`、`create_auth_service`、`create_multi_user_clients`、`create_api_client_from_file`）。

## 层间规则

1. 高层依赖低层，禁止反向依赖。
2. 底层错误在 HTTP/仓储边界转为领域异常后向上抛出。
3. 多用户场景为每个 `Credential` 独立客户端与缓存命名空间，互不污染。

测试上可按层 Mock；集成时通过工厂组装，与生产路径一致。
